# Gateway One · 订阅网关

一条命令，把你自己账号的 **Claude Max / ChatGPT / xAI Grok** 变成本地可用的 API，附带一个可视化控制台。

给的不是"另一个代理服务器"——市面上已经有十几个了。给的是**不用碰命令行的最后一公里**：装完自动打开浏览器，之后加账号、测模型、看额度、管 Key、做备份，全在网页上点。

```
一条命令  →  网关跑起来  →  浏览器自动打开  →  点「+ 添加账号」  →  能用
```

---

## 一、装

```bash
bash install.sh
```

会先问你三件事（都可以回车走默认）：

1. **要接哪几家** —— Claude Max / ChatGPT / xAI Grok，可多选
2. **谁能访问** —— 只本机 / 局域网 / Tailscale 跨网
3. **开几把客户端 Key** —— 默认 3 把（一台设备一把）

然后它自己做完这些：

| 步骤 | 做什么 |
|---|---|
| 探测 | CPU 架构、macOS/Linux、curl/tar/openssl、有没有 sha256 工具、钥匙串可用性 |
| 连通 | 直连 → 环境变量代理 → 本地常见代理端口（7890/7897/1080/1087）逐个真打一次 `api.anthropic.com` |
| 下载 | 查 GitHub 最新 release，下对应资产，**用官方 `checksums.txt` 校验 SHA256**，解包、去隔离属性 |
| 配置 | 生成 `config.yaml`（三通道 model-alias、代理、重试、日志）+ 3 把随机 Key + 管理口令 |
| 常驻 | macOS → launchd（KeepAlive）；Linux → systemd（Restart=always），含 `Umask 077` |
| 看护 | 装 watchdog：5 分钟自检，分类处置（端口没听→重启 / 401→只告警 / 429→只记录 / 连续 3 次 5xx→重启） |
| 备份 | 装 backup.sh：每天一次 AES-256 加密打包 auth + config，口令进钥匙串，留 7 份 |
| **控制台** | 装 Web 面板并拉起，**自动打开浏览器** |

装完屏幕上是地址、Key、各客户端怎么填。

**重装安全**：已有 Key 会被复用（不会让你已经配好的设备突然失效），旧配置自动备份成 `.bak`。

## 二、加账号（这是重点）

传统做法：在终端跑 `./cli-proxy-api -claude-login`，把设备码复制到浏览器，再回终端看结果。

这里：点按钮。

```
+ 添加账号  →  选平台  →  网页上显示大字设备码 + 倒计时  →  你去浏览器输入  →  这边自动完成
```

- **不需要终端**，也不需要复制粘贴任何东西
- 设备码会**自动复制**（点一下码块）
- 「打开授权页」按钮直接跳转
- 后端每 1.5 秒轮询真实登录进程的输出，成功即提示「已连接」，**无需重启网关**（热加载）
- 有倒计时。xAI 30 分钟、ChatGPT 15 分钟、Claude 7 分钟——**过时了会明说，可以一键重来**

技术上是怎么做到的：把 `cli-proxy-api` 的登录子进程挂在**伪终端**（`pty.openpty`）上跑，实时读它的输出抓设备码。直接 `subprocess` 拿不到码，因为它在没有 tty 时会因 stdin EOF 直接退出——这是这套东西最容易踩的坑。

## 三、控制台里还能干什么

| 区块 | 内容 |
|---|---|
| **链路图** | 订阅（邮箱 + 凭证剩余有效期 + 权限位）→ 网关（端口/PID/uptime/内存/版本）→ 客户端 Key（可复制明文），动态 SVG 连线 |
| **模型矩阵** | 全部模型分组（别名 / Claude / Grok / Codex）+ 搜索，**点一张卡就真发一次请求**，返回毫秒数和回显的真实模型名 |
| **额度与故障** | 从错误日志反推：额度用尽（带重置倒计时）、模型冷却、限流 429、鉴权失败 |
| **事件流** | watchdog + backup 日志合并，连续相同折叠成 `×18` |
| **运行明细** | 监听地址、局域网地址、出口代理、重试次数、凭证数、调用样本、成功率、延迟 p50/p95 |
| **接入客户端** | 六种客户端的 Base URL，按协议标好带不带 `/v1`，一键复制 |

按钮都是真执行：重启网关（`launchctl kickstart -k`）、停止（`bootout`）、备份（跑 `backup.sh`）。

**额度栏的诚实说明**：三家都不开放余额查询接口。这一栏是「已经发生的事实」——谁什么时候撞了限额、多久后重置。准，但它是事后而非预测。剩下多少只能去各家网页端看。

## 四、卸载

```bash
bash ~/claude-gateway/uninstall.sh
```

移除三个服务（网关 / 看护 / 控制台）、plist、网关目录。**备份保留**。没有系统级残留。

---

## 五、已知的硬限制

1. **额度不叠加** —— 三家各自的订阅额度，多设备共享同一份窗口。并发多了照样 429，控制台里能看见。
2. **伪装层是逆向的** —— 上游只认 Claude Code 的 OAuth 指纹，网关必须套它的系统提示，所以模型会自称「Claude Code，Anthropic 官方命令行工具」。上游一改校验方式就会失效，这是这类工具的共同命门。
3. **命脉在 CLIProxyAPI** —— 本项目是它的封装 + 界面，不是替代。它从 v1 到 v8 做过一次破坏性重构（`host`/`port`/`api-keys` 全改名），以后可能再来一次。所以安装器**不锁版本、不自动升级**，升级前留 `.prev` 可 10 秒回滚。
4. **设备码必须有人在** —— 加账号时人要能去浏览器点确认。这不是设计缺陷，是 OAuth 的本质。
5. **控制台只绑 127.0.0.1** —— 手机打不开。要开放得走 Tailscale 并且加认证。
6. **需要 python3** —— 控制台用它（macOS 装 Xcode 命令行工具即可）。网关本身是单个静态二进制，不需要任何运行时。
